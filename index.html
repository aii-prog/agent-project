1. 对话主流程

每一轮对话都走这条流程。高频固定问题先由 QA 对直接回答；其余问题结合历史对话判断意图类型，只有“有效咨询”进入 Skill 和工具调用，其他四类各有固定的处理策略。

QA 对前置

起订量、发票、营业时间这类答案固定的问题，命中 QA 对就直接回答，不经过意图判断和大模型。回答稳定，也省成本和时延。（演示场景 4）

5 类意图分流

先判断“这句话属于哪一类”，再决定要不要进 Skill。闲聊、需求不明、情绪宣泄都有专门的应对，不会被硬塞进业务 Skill 里答非所问。（演示场景 4、5）

工具结果校验回环

工具返回后先判断能否满足需求。不满足就回到 Skill 重新决策，比如候选太多就反问参数，批量价查不到就改走询价流程。（演示场景 1、2）

转人工计数规则

近 5 轮内转人工诉求或负面情绪累计 3 次才转人工，之前先安抚并尝试解决。这是转人工率下降 40%+ 的关键设计，同时保证真着急的客户不会被困住。（演示场景 5）

2. 意图类型与二级意图

第一层是 5 类对话意图类型；“有效咨询”下再按业务拆成二级意图，每组二级意图对应一个 Skill 和一套 SOP。（二级意图名称为示例）

转人工计数规则判断：转人工，或安抚引导
闲聊 / 结束语引导到可咨询范围，或礼貌结束
有效咨询命中 Skill → 调用工具 → 校验 → 回答
需求不明给出选项，引导澄清，不猜
情绪宣泄先安抚，再引导回具体问题

3. Skill 触发边界与工具调用规则

每个 Skill 写清楚“什么时候做、什么时候不做、工具结果不满足时怎么办”。复合意图拆成子任务，彼此不依赖的工具并行调用，有依赖的串行。

Skill触发不做（边界）工具与调用方式结果不满足时
产品参数查询规格、选型、尺寸公差、材质不回答资料里查不到的参数，不给强度计算的最终结论search_parts → 规格校验；get_price ‖ get_lead_time 并行候选过多 → 反问关键参数（最多 3 个，给选项）
报价采购单价、阶梯价、交期、下单不承诺折扣，不改价get_tier_price ‖ get_lead_time 并行 → 汇总无自动价格（≥300 或议价）→ create_sales_lead 生成询价单给营业
竞品对比他司型号替换、规格对照只做规格对照，不评价他司质量与价格；对照表未收录不推测xref_lookup → 关键尺寸逐项比对（串行）有差异项 → 回答中必须写明风险；需要看图纸 → 技术咨询工单
售后支持订单、物流、退换货、技术咨询不判定质量责任get_order；create_tech_ticket查不到订单 → 反问订单号

4. SOP：“理想回答”标准（以选型推荐为例）

内容
必须包含完整型号、选型理由、注意事项；缺关键参数时先澄清，不猜
结构
结论 → 推荐型号 → 理由 → 注意事项 → 下一步操作
长度
正文 ≤250 字；参数用标签或表格，不写成长段落
语气
专业、简洁；不用“最好”“绝对”等夸大表述
澄清
一次最多问 3 个问题，每个都给选项
BEFORE · 关键词问答对

“直线轴有多种材质和尺寸可选，请参考产品目录第 42 页，或联系营业担当。”

没有型号，客户要自己翻目录

AFTER · 按 SOP 生成

“推荐 LSF-S-D12-L230-TM6。洁净室需要低发尘，不锈钢淬火轴无镀层……注意：3kg 负载建议两根轴并联。”

可直接加入询价单

5. 架构演进

PoC 阶段

Planner + Executor

意图识别→检索召回→多轮上下文→信息澄清→内容生成
  • 链路清晰，适合快速验证“能不能答对”
  • 每加一个意图都要改 Planner 的整体 Prompt，互相影响
  • “价格 + 交期”这类复合意图只能串行处理，容易只答一半
迭代后（上面的主流程）

Agent + 可插拔 Skill

产品参数报价采购竞品对比售后支持+ 新 Skill
  • 每组二级意图封装成独立 Skill，新增意图只加 Skill，不动其他部分
  • 复合意图拆成子任务，无依赖的工具并行调用
  • 边界写在 Skill 里，Bad Case 能定位到具体 Skill

四维评估框架

准确性型号、参数、价格、交期是否与数据源一致。任何一个数值错误即判为不合格
相关性是否回答了客户真正问的；复合问题是否每一问都覆盖
逻辑一致性多轮中前后不矛盾；“刚才那根”能正确指代上文型号
专业表达是否符合 SOP 的结构、长度、语气；术语是否规范

断点 + 端到端两层离线评测

断点评测（节点级）

分别评意图识别、槽位抽取、检索召回、生成，定位是哪一个节点出错，避免只看最终答案“猜原因”。

端到端评测

按线上真实问题分布抽样，看整轮对话是否帮客户完成任务，作为每次迭代上线前的回归门槛。

Bad Case 归因顺序：链路缺陷 → 策略问题 → Prompt / 模型问题

先排查成本最高、影响面最大的链路问题，最后才动 Prompt。下面是三类问题的示例（内容已虚构化）。

1洁净室场景推荐了镀铬轴链路缺陷

断点评测发现检索没有召回“洁净环境材质”章节：规格表被切块时表头和行被切开。

修复：表格按“表头 + 行”切分，分层检索召回整节内容。

2问“价格和交期”只答了价格策略问题

复合意图被当成单一意图处理。

修复：意图识别输出多标签，Agent 拆成子任务并行调用工具后再汇总。

3回答冗长，型号埋在段落中间Prompt 问题

生成没有遵守 SOP 结构。

修复：Prompt 按 SOP 分段约束 + Few-shot 示例，结论和型号放第一行。
